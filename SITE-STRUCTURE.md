## Internal linking rules (enforce in the day-2/day-4 passes)

1. **Body links beat footer links.** The audit found heavy footer/"Popular SEO pages" repetition (79 anchors, 21 link cards, 15 H2s on the homepage, three near-duplicate guide grids). Each spoke must earn **≥1 in-body contextual link** from its cluster parent — not just a footer entry.
2. **Hub-and-spoke:** `/` is the hub; every tool and guide links up to its cluster parent and sideways to at most 2 siblings.
3. **Descriptive anchors:** anchor text = the target query ("when correction should stop"), never "read more"/"this guide".
4. **Footer consolidation:** collapse the three homepage link grids into one; remove the literal "Popular SEO pages" label (jargon visible to users and crawlers).
5. **Orphan check:** re-run `onpage_check.py` after edits — `internal_links` per page must not drop.

## Sitemap structure (quality gates)

- 16 URLs, no location-style programmatic pages → **no thin-page gate risk** (warning threshold is 30+ pages of one type; hard stop at 50+).
- `lastmod` must come from actual content modification dates once the generator is in `build`.
- Keep `priority`/`changefreq` as-is; they are advisory only.
- Every sitemap URL must remain 200 + self-canonical (currently true — treat as a regression check each audit).

## Domain decision (prepared, not executed this week)

**Problem:** `preemie.vercel.app` is a shared platform subdomain — link equity accrues to `vercel.app`, brand searches return nothing, and it reads as a preview deployment.

**Options:**

| Option | Pros | Cons |
|---|---|---|
| **A. Stay on preemie.vercel.app** | Zero risk, no redirect work, GSC already documented against this host | Permanent authority ceiling on a shared subdomain |
| **B. Move to an own domain (e.g. drzeewrites.com subdomain or a fresh exact-match domain)** | Real brand, real DA accrual, credible in citations and outreach | Needs DNS + 301 map + GSC property + re-verification; loses the week's measurement if done mid-flight |
| **C. Separate path host on own domain (`adjustedage.com`)** | Best long-term brand fit for a tool+publisher hybrid | Same cutover cost as B |

**Recommendation:** decide **B vs C** on day 1, **execute no earlier than the week after** — after GSC is verified and a crawl baseline exists. Cutover checklist:

1. Purchase + point apex, www, and legacy host.
2. 301 map: every one of the 16 URLs individually (no domain-wide wildcard — path structure is unchanged, so it is a host-level 301 plus per-URL safety net).
3. New GSC property for the new host; keep the old one for monitoring; submit sitemap there.
4. Update canonical, `og:url`, `Organization.url`, JSON-LD `@id`, `llms.txt`, `llm.txt`, README/docs references (`SEO-CONSOLE-SETUP.md`, playbook) in **one commit**.
5. Update `scripts/generate-sitemap.mjs` BASE constant.
6. Verify all 16 return 200 on new host, then request indexing for `/`.
7. Keep old host serving 301s for ≥6 months.

**Do not** run two live hosts with identical content — that is duplicate content across hosts with split signals.
