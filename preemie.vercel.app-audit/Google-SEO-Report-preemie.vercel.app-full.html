This report presents a comprehensive SEO audit of preemie.vercel.app for a Publisher / YMYL health tool (calculator + editorial guides) site, generated on September 28, 2026. Findings combine technical, content, schema, performance, visual, and search-readiness evidence as available.

2. Audit Categories

2.1 Technical SEO

Score: 85/100

What Works

  • All 16 sitemap URLs return 200 with exact self-canonical and index,follow
  • 16 unique titles and H1s; no noindex anywhere in src/
  • Sitemap valid and declared in robots.txt
  • HTTP to HTTPS single 308; HSTS max-age=63072000 includeSubDomains preload on every response
  • No redirect chain longer than 1 hop; no indexable parameter/case/dot-segment variants
  • 0 images missing width/height across 16 pages (no CLS from images)
  • Module scripts + modulepreload; immutable caching on hashed assets

Findings

public/favicon.png is a Vercel 503 error page served as image/png High

public/favicon.png is a committed 447-byte XHTML '503 first byte timeout' document served with Content-Type image/png. It is referenced by rel=icon and by WebSite.publisher.logo JSON-LD. /favicon.ico returns 404. This is a regression versus the 2026-08-26 audit, which recorded a 4 KB icon.

Recommendation: Replace public/favicon.png with a real rendered icon (32x32 PNG plus 180x180 apple-touch-icon), add a /favicon.ico, and verify WebSite.publisher.logo points at a valid logo image.

Security response headers missing Medium

No Content-Security-Policy, X-Content-Type-Options, Referrer-Policy, Permissions-Policy or X-Frame-Options on any response; no vercel.json in the repo to set them.

Recommendation: Add a vercel.json headers block setting X-Content-Type-Options: nosniff, Referrer-Policy: strict-origin-when-cross-origin, X-Frame-Options: DENY, a conservative Permissions-Policy, and a CSP appropriate for the TanStack Start build.

Sitemap lastmod uniformly 2026-08-26 and generator not part of build Medium

Every sitemap entry reports lastmod 2026-08-26 although content shipped on 2026-08-27. scripts/generate-sitemap.mjs is not invoked by the build script, so public/sitemap.xml drifts whenever routes change.

Recommendation: Wire generate-sitemap.mjs into the build (or a prebuild step) and derive lastmod from actual content modification dates.

Google Fonts render-blocking third-party CSS on all 16 pages Medium

Fonts load via third-party Google Fonts CSS plus 6 woff2 files (approx 299 KB), render-blocking on every route. Still open from the 2026-08-26 audit.

Recommendation: Self-host the font CSS and preconnect/preload the woff2 files, or system-font stack the critical path.

Large initial JavaScript payload (INP risk) Medium

The homepage preloads a 257 KB gzipped chunk containing jsPDF (86 refs) and Recharts (74 refs); total initial JS is approximately 398 KB gzipped. Field INP is not measurable (no CrUX/PageSpeed credentials).

Recommendation: Code-split jsPDF (export/print) and Recharts (chart view) behind dynamic import so the calculator path ships neither.

404 route is indexable and inherits homepage metadata Low

The 404 response returns status 404 but serves meta robots index,follow, no canonical, and the homepage title/og:url.

Recommendation: Serve a dedicated 404 title, keep the status 404, and add meta robots noindex to the not-found route.

Case-variant URLs return 200 Low

Paths such as /About return 200 rather than 308 to the lowercase canonical. Canonical tags currently prevent duplicate indexing.

Recommendation: Normalise path case at the edge or route layer with a 308 to the canonical URL.

Trailing-slash variants redirect with 307 instead of 308 Low

Trailing-slash variants answer 307 (cacheable temporary redirect) rather than 308 (permanent), so crawlers may re-evaluate them indefinitely.

Recommendation: Change trailing-slash redirects to 308.

Service worker path 404s while the PWA registers it Low

/sw.js returns 404 although src/pwa.ts registers it, so the visible 'Works offline' badge is not backed by a working offline path.

Recommendation: Ship the built service worker at /sw.js or remove the offline claim and the registration.

www subdomain fails TLS with no redirect Low

www.preemie.vercel.app has no valid certificate and no redirect to the apex host.

Recommendation: Add a certificate/redirect for www, or leave intentionally disabled and document it.

2.2 Content Quality

Score: 70/100

What Works

  • Byline + dated review line on 16/16 pages, real physician headshot, Physician/sameAs/reviewedBy schema
  • Editorial policy, funding/COI policy, sitewide medical disclaimer, red-flag cross-links on 16/16
  • Internal linking strong (84): every page links forward into the calculator cluster
  • Answer-first 'Quick answers' blocks and a 7-question FAQ on the homepage

Findings

No outbound citation links on 15 of 16 pages High

CDC/AAP/WHO/Fenton/INTERGROWTH appear as bare text only. The /methodology Sources table (Fenton PMID 23601190, INTERGROWTH, Zubler 2022) is plain text and unlinked, and JSON-LD carries no citation property. YMYL claims are therefore unverifiable from the page itself.

Recommendation: Link every named authority and each methodology source to its primary URL (target/PubMed/DOI) and add matching 'citation' entries to the MedicalWebPage/Article JSON-LD.

Thin content: 11 of 16 pages under 800 words in <main> High

Median page is 630 words. /red-flags has 526 total words of which only 166 are prose; /how-to-calculate-corrected-age has 559; /nicu-follow-up-schedule 585. For a YMYL competitive query set this is below the depth peers publish.

Recommendation: Expand /red-flags, /how-to-calculate-corrected-age and /nicu-follow-up-schedule first with concrete worked examples, source-backed detail and unique first-hand clinical context; do not pad thin utility pages with filler.

Readability below grade-8 target on 15 of 16 pages Medium

Median prose Flesch 46.8 (about grade 10). Worst: /nicu-follow-up-schedule 41.1, /preemie-vaccines 41.2, /about 42.3. Audience is anxious parents reading on mobile at night.

Recommendation: Shorten sentences and unpack clinical terms on the parent-facing pages; keep the clinician register on /pma-calculator and /methodology.

Keyword cannibalization across calculator and comparison pages Medium

Cosine overlap: / vs /adjusted-age-calculator 0.64, / vs /pma-calculator 0.64; the age-comparison topic is spread over 4 pages (0.49-0.55); vaccines appear on 6 pages (0.52 vs /preemie-vaccines); stop-correcting covered by 4 pages.

Recommendation: Assign one canonical URL per query cluster, trim the overlapping sections on the secondary pages and point their internal links at the canonical - consolidate sections, do not delete pages.

Titles and meta descriptions exceed recommended lengths Medium

7 titles over 60 characters and 8 meta descriptions over 160 characters, risking SERP truncation; '| AdjustedAge' brand suffix is missing on /when-to-stop-correcting.

Recommendation: Rewrite the 7 titles and 8 descriptions to fit 50-60 / 150-160 characters with the primary keyword front-loaded and a consistent brand suffix.

No direct contact or corrections channel Medium

Contact is described as 'via the about page' with no email/form, and there is no corrections log - both are trust signals Google's quality rater guidelines expect for YMYL health sites.

Recommendation: Publish a contact address or form on /about and add a dated corrections log.

Milestone 'chart' has no tabular or downloadable artifact Medium

The page called a chart renders 72 list items; the whole site has only 3 <table> elements and no CSV/PDF download.

Recommendation: Render the milestones as a real table with a CSV/print export to match the 'chart' query intent and earn citations.

2.3 On-Page SEO

Score: 85/100

What Works

  • 16/16 pages return 200 with exactly one H1, a self-referencing canonical, viewport meta and no heading-level skips
  • 16/16 carry complete Open Graph (title, description, image, url, type) and Twitter card tags
  • 256 internal links across 16 pages (avg 16/page) with descriptive anchor text into the calculator cluster
  • Every page has a unique title and unique meta description (no templates or duplicates detected)

Findings

7 titles exceed 60 characters Medium

Independent crawl of all 16 sitemap URLs found 7 titles over 60 characters, which Google will truncate in the SERP, hiding the brand suffix and possibly the primary keyword.

Recommendation: Cut each to 50-60 characters, front-loading the primary keyword and keeping '| AdjustedAge' at the end.

8 meta descriptions exceed 160 characters and 1 is short Medium

8 descriptions run past 160 characters (truncated mid-sentence in SERPs) and 1 is under 120 characters, wasting the click-through opportunity.

Recommendation: Rewrite to 150-160 characters opening with the answer, not a restatement of the title, and closing on a concrete benefit rather than a stock CTA.

Brand suffix missing on /when-to-stop-correcting Low

The only title in the set without the '| AdjustedAge' suffix, breaking brand consistency in SERPs and OG previews.

Recommendation: Restore the suffix to match the other 15 titles.

Thinnest page carries only 599 words Low

Minimum word count across the 16 URLs is 599 (median 859), so at least one page sits under the depth expected for its query class.

Recommendation: Identify the sub-600-word page in onpage.json and expand it with source-backed, unique content.

2.4 Schema / Structured Data

Score: 74/100

What Works

  • 16/16 sitemap URLs emit JSON-LD: 82 blocks, 82/82 parse-valid, 0 truncated, all @context https, all URLs absolute, all dates ISO-8601
  • Physician @id resolves on 16/16 pages; every author/reviewedBy/copyrightHolder/creator reference resolves
  • WebApplication emitted on exactly the 4 tool routes, with applicationCategory HealthApplication and offers price 0
  • All 11 og/*.png URLs referenced by schema return 200 as real 1200x630 PNGs; Physician.image claims 709x585 and the live PNG is 709x585
  • No fabricated aggregateRating or Review markup

Findings

Organization.logo points at a file that is not an image (16/16 pages) High

Organization.logo resolves to the 447-byte Vercel 503 XHTML page served as image/png, so every logo/organization validation fails sitewide. Same root asset as the technical F1.

Recommendation: Regenerate public/favicon.png as a real PNG and point Organization.logo at public/icons/icon-192.png (verified 192x192, 32 KB).

Duplicate, conflicting Physician node on /about High

about.tsx emits a second Physician with the same @id already defined in __root.tsx, with different description and extra properties, so JSON-LD merging is order-dependent.

Recommendation: Fold the richer property set into the single __root.tsx node and delete the duplicate block in about.tsx.

/about has no page-level schema node at all High

/about emits only WebSite, two Physician copies and BreadcrumbList: no WebPage/ProfilePage, no dates, no publisher, on the page carrying all YMYL identity weight.

Recommendation: Add a single ProfilePage (or WebPage) node with dates and publisher, after resolving the duplicate Physician.

Organization exists only as 31 anonymous inline copies Medium

31 Organization nodes sitewide carry no @id, so they can never be referenced, merged or enriched; MedicalWebPage.copyrightHolder points at the physician rather than the publisher.

Recommendation: Define one @id-keyed Organization with sameAs and url, and replace the anonymous copies with references.

medicalSpecialty value 'Pediatrics' is not a valid enum member Medium

schema.org's MedicalSpecialty enumeration member is 'Pediatric'; the string 'Pediatrics' is used in 14 source locations and therefore renders on all 16 pages.

Recommendation: Replace with 'Pediatric' (or the full https://schema.org/Pediatric URL) in all 14 spots; free-text knowsAbout is fine as-is.

image missing from 9 page nodes Medium

MedicalWebPage.image missing on 7 URLs and Article.image on the 2 guide pages, even though every one already has an og:image meta tag and a live 1200x630 card.

Recommendation: Point each node's image at the OG card that already exists for that page.

Two guide pages use Article only, with no medical review wiring Medium

/premature-baby-milestones and /how-to-calculate-corrected-age emit Article with author and publisher but no lastReviewed, reviewedBy, audience or specialty, despite a visible review line, violating the repo's own SEO-AUDIT.md rule.

Recommendation: Add the MedicalWebPage node plus reviewedBy/lastReviewed to match the site-wide pattern.

/privacy is typed MedicalWebPage Medium

A privacy policy is declared as MedicalWebPage with no medical audience, specialty or reviewer.

Recommendation: Retype as WebPage.

Schema dates drift from sitemap lastmod on 13 pages Low

dateModified/lastReviewed read 2026-08-27 while sitemap lastmod was frozen at 2026-08-26, so crawlers saw two competing current dates.

Recommendation: Regenerate the sitemap at build time and keep schema dates in sync with the visible review line.

Breadcrumb name differs from the visible label on 13/16 pages Low

Case-only differences on 10 pages and wording differences on 3 (e.g. schema 'Premature Baby Milestones' vs visible 'Premature baby milestones chart').

Recommendation: Make each BreadcrumbList name match the visible breadcrumb text exactly.

FAQPage markup does not match the visible copy Low

Of 46 marked-up questions only 13 appear verbatim on-page, and 5 pages carry FAQPage with no visible Q&A section. Recorded as integrity only: Google retired FAQ rich results on 2026-05-07, so there is no SERP feature at stake and this is NOT a recommendation to add or remove FAQPage.

Recommendation: Regenerate the JSON-LD strings from the copy already on the page, or render the marked-up Q&A visibly. Info priority, no new FAQPage.

HowTo block on /how-to-calculate-corrected-age earns nothing Low

Google removed how-to rich results in September 2023; the steps are honest visible copy but the markup has no SERP value.

Recommendation: Optional cleanup: remove the block. Never add HowTo anywhere else.

2.5 Performance (CWV)

Score: 71/100

What Works

  • Viewport meta, html lang and explicit image width/height on all 16 pages (zero CLS risk from images)
  • Module scripts plus modulepreload; hashed /assets/* served with Cache-Control public, max-age=31536000, immutable
  • True SSR: h1, FAQ text and 6 JSON-LD blocks present in the raw response, so LCP is server-delivered HTML rather than client render
  • 13 OG cards are fixed 1200x630 PNGs with og:image:width/height declared

Findings

Google Fonts render-blocking third-party CSS on all 16 pages Medium

Two serialized round-trips (Google CSS then gstatic font files) sit on the LCP path; the homepage h1 is set in font-display Newsreader, so LCP text stays invisible until the webfont resolves. Still open from the 2026-08-26 audit.

Recommendation: Self-host via @fontsource-variable/newsreader and @fontsource-variable/public-sans (both OFL), preload only the LCP weight, drop both preconnects.

Large initial JavaScript payload (INP risk) Medium

The homepage preloads a 257 KB gzipped chunk containing jsPDF (86 refs) and Recharts (74 refs); total initial JS is about 398 KB gzipped, pressuring INP on mid-range mobile — the device a parent uses at 3 a.m.

Recommendation: Code-split jsPDF (export/print) and Recharts (chart) behind dynamic import so the calculator path ships neither.

Three avatar images compete with the LCP element at high priority Low

Hero, sidebar and footer avatars all carry fetchPriority=high and loading=eager, including a 64 px footer image below the fold; all three contend with the h1 for the limited-connection priority queue.

Recommendation: Reserve fetchPriority=high for the LCP candidate and lazy-load the footer avatar.

Public images are served with Cache-Control max-age=0, must-revalidate Low

Author photo, OG art, favicon and manifest revalidate on every load, while hashed assets are immutable.

Recommendation: Give public/ images a real TTL such as max-age=604800, stale-while-revalidate=86400.

No field Core Web Vitals available Medium

No CrUX, PageSpeed or GSC credentials are configured, so INP and LCP cannot be confirmed against the 2.5 s / 200 ms thresholds.

Recommendation: Verify the property in Search Console and enable the PageSpeed Insights API so the next audit reports measured CWV instead of inference.

2.6 AI Search Readiness

Score: 76/100

What Works

  • Every major AI crawler (GPTBot, ClaudeBot, Claude-Web, PerplexityBot, Google-Extended, CCBot, bingbot, msnbot, OAI-SearchBot) receives 200 with a byte-identical 55,643-byte body - no blocking, no cloaking, no X-Robots-Tag
  • robots.txt permissive (Allow: /) with sitemap declared; only /mcp, /.mcp/, /.well-known/, /~oauth/ disallowed
  • llm.txt and llms.txt both live and byte-identical (4,088 B), covering 16/16 sitemap URLs
  • Answer-first structure: 'Quick answers' / 'The short answer' blocks, 7-question FAQ, Physician + reviewedBy + sameAs graph on every page, datePublished/dateModified/lastReviewed, true SSR
  • Brand consistency: AdjustedAge + preemie.vercel.app identical across og:url, canonical and site_name on 16/16 pages

Findings

llms.txt entries are not links and not absolute URLs High

Entries are formatted as '**/path** - description' rather than markdown links with absolute URLs, so link-extracting AI parsers recover zero URLs from the file.

Recommendation: Regenerate llms.txt with '[Title](https://preemie.vercel.app/path)' link syntax for all 16 pages.

Zero outbound source links citable by AI systems High

Authority sources are named as plain text only across all 16 pages, so an answer engine extracting claims cannot cite a verifiable source from this site. Same root cause as the content-side citation gap.

Recommendation: Add primary-source links to CDC/AAP/WHO/Fenton/INTERGROWTH references and mirror them in JSON-LD 'citation'.

Article schema missing reviewedBy and lastReviewed on two spoke pages Medium

/premature-baby-milestones and /how-to-calculate-corrected-age carry Article schema without reviewedBy/lastReviewed, unlike the rest of the site.

Recommendation: Add reviewedBy (Physician @id) and lastReviewed dates to match the site-wide pattern.

Organization.logo points at the broken 447-byte favicon Medium

Organization.logo still references the invalid favicon asset identified in the technical pass, weakening entity recognition.

Recommendation: Point Organization.logo at a real 1148x1148 (or larger) logo image and keep it referenced by ImageObject.

Title brand drift on one page Low

/when-to-stop-correcting omits the AdjustedAge brand suffix present on the other 15 titles.

Recommendation: Restore the consistent '| AdjustedAge' suffix.

Findings

The favicon is a 447-byte Vercel 503 XHTML page served as image/png and /favicon.ico returns 404, so the browser tab and search sitelink favicon are broken sitewide.

Across 16 pages there is a single crawlable content image (the rest are avatars, OG art and icons), so image search brings no traffic and visual results give the site nothing to show for the milestones and growth-chart queries.

Recommendation: Add bespoke diagrams — a corrected-age timeline, the milestones chart as an image, and a growth-curve explainer — each with descriptive filenames, alt text and matching schema image.

498 KB PNG fallback behind the author photo Low

Browsers without WebP support download a 498,507 B PNG for a headshot rendered at 40-96 px.

Recommendation: Resize the PNG fallback to at most 2x its largest rendered size.

Avatar images use fetchPriority=high and eager loading below the fold Low

Three avatars including the 64 px footer image request high priority, competing with the LCP element.

Recommendation: Keep high priority for the LCP candidate only; lazy-load the rest.

Public images revalidate on every request Low

Cache-Control max-age=0, must-revalidate on public/ images means repeat visits re-fetch the author photo and OG art.

Recommendation: Set a one-week TTL with stale-while-revalidate.
